# Discord 관리 담당

프로젝트 카테고리와 작업·기획·할일·결재함·완료·막힘·사무실-대화 채널의 생성·보충은 **백서진(비서실장)** 인증으로 수행한다. Hermes의 기존 `.env`에서 `DISCORD_BOT_TOKEN`만 읽으며 별도 봇 로그인이나 토큰 복사본은 만들지 않는다. 비서실장 인증이 없으면 새 채널 생성은 대기하고 LINDA로 우회하지 않는다.

LINDA는 슬래시 명령 접수, 전체 시스템 소식, 직원 메시지 전달을 위한 내부 연결을 맡는다. LINDA의 봇 역할에는 채널 보기·메시지 전송·링크·파일·기록 읽기·공개 스레드 생성·스레드 메시지 전송만 남긴다. 채널 관리·역할 관리·서버 관리·관리자 권한을 부여하지 않는다. `@everyone`에서 상속하는 일반 권한은 별도이며, 다른 직원이나 사용자의 역할을 바꾸지 않는다.

백서진은 기존 **관리자** 권한을 유지하고, 봇 역할 중 가장 위에 둔다. Discord의 역할 순서는 관리자가 가진 권한과 별도로 적용되므로, 현재 자기보다 위에 있는 LINDA 역할을 백서진이 스스로 낮출 수는 없다. 서버 소유자가 **서버 설정 → 역할 → 백서진(비서실장)을 LINDA보다 위로 이동**해야 한다. 관리자 권한을 새로 더하는 작업은 필요 없다.

역할 순서 변경 뒤 `node scripts/discord-authority.mjs --apply`를 실행하면 백서진 인증으로 LINDA의 관리 권한을 제거하고 결과를 재조회한다. 순서가 맞지 않으면 변경 전에 멈춘다. `--apply`가 없는 실행은 조회만 한다. 토큰은 출력하지 않는다. 변경 전 역할과 채널 덮어쓰기는 `C:\ai-office\data\discord-authority-before.json`, 최신 점검 결과는 `discord-authority-latest.json`에 저장한다.

Discord 역할 변경은 회사의 CEO 결재 규칙을 바꾸지 않는다. 계획서·푸시·배포 등은 기존 결재 절차를 따른다.

검증: `npm run typecheck`와 `chief-authority`, `project-channels`, `role-notifications`, `new-project` 테스트. 실제 연결은 `Discord 채널 관리 담당: 백서진(비서실장)` 시작 로그와 관리 인증의 Discord 계정 조회로 확인한다.
